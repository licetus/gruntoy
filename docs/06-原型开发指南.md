## 0. 这份指南与上游文档的关系（先读这一节）

本指南**不替代**上游三份清单，而是把已交付的 v1.0 固件接进它们的流程。

上游清单写于固件不存在之时，其中 **4 项「写代码」任务已被 v1.0 覆盖**：

| 上游清单中的任务 | 上游清单里的做法 | v1.0 之后的做法 |
|---|---|---|
| 体感 Day2「ESP32 PWM 输出占空比」 | 从零写 PWM 代码 | `t bare <duty>` |
| 体感 Day4「写呼吸包络代码」 | 从零写正弦包络 | `t breath 1\|2\|3` |
| 体感 Day5「写咕噜代码」 | 从零写 25~50Hz 包络 | `t purr` / `t sweep` / `t gate` |
| 体感 Day7「用串口模拟心情值累积」 | 从零写状态机 | `t feed` / `t mood` / `t cycle` |

**一句话：上游清单教你造工具，本指南教你用工具。**

因此可执行动作从「写代码 + 调参」压缩为「**发命令 + 记录 + 回填参数**」。省下的时间应投入到盲测被试招募与噪声实测上——那两件事才是门禁证据的来源。

### 0.1 必须知道的两处参数现状

**① 参数已从 58 项扩为 75 项。**
PRD 附录 C 的数组型参数（`purr_tier_boundaries`、`tail_freq_hz`、`tail_amp`、`breath_intensity_levels` 等）在固件中展开为独立标量项，并补齐了上游缺失的 P-16 降落曲线、P-24 线性映射模式、P-30 / P-31 两道闸门。
完整对照见 [`03-参数体系与校验规则.md`](03-参数体系与校验规则.md)。**回填附录 C 时按 75 项粒度填，不要按数组填。**

**② `purr_tier_d0~d3` 的数值已刻意偏离 PRD。**

| 来源 | 数值 |
|---|---|
| PRD P-26 `purr_tier_durations_ms` | `[20000, 30000, 45000, 60000]` |
| v1.0 固件 `purr_tier_d0~d3` | `[20000, 32000, 46000, 60000]` |

原因：原值在心情值 **104 → 105** 处单点跳变 10 秒——用户视角是「摸到某个点突然多震 10 秒」，违反 FR-40「不可跳跃切换」。修正后单点最大跳变从 10000ms 降到 2800ms，曲线连续单调。

**这两个数都是估算值。** Day 5~7 上手听之后必须**同时更新固件与 PRD**，否则 M1 门禁的「更新附录 C」这一步会留下不一致。

## 1. 目标：M1 门禁的 7 项证据

M1 门禁 = 下表 7 项**全部有数据填进去**。数据好不好是另一回事，但必须有数据。

| # | 门禁要求 | 证据形式 | 产出动作 | 本指南 |
|---|---|---|---|---|
| 1 | 机构寿命 ≥1 万次不失效 | 寿命测试记录表 + 拆解磨损照片 | 摇尾线 Day 8-10 | §5.5 |
| 2 | 模式盲测可区分 | 盲测记录表（辨识率 ≥70%） | 体感线 Day 6 | §4.6 |
| 3 | 呼吸噪声实测达标 | 噪声记录表（≤40dB @30cm） | 体感线 Day 2 / 3 / 5 | §4.2 ~ 4.4 |
| 4 | 咕噜噪声实测达标 | 噪声记录表（≤45dB @30cm） | 体感线 Day 5 | §4.5 |
| 5 | 咕噜辨识率 ≥70% | 盲测合计行 | 体感线 Day 6 | §4.6 |
| 6 | 摇尾执行器选型结论 | 选型评分表 + 决策理由 | 摇尾线 Day 11-14 | §5.6 |
| 7 | W4 档 2.0Hz 可达性 | 频率对比表 | 摇尾线 Day 3-7 | §5.3 ~ 5.4 |

### 1.1 要验证什么，不要验证什么

| ✅ 要验证（本次） | ❌ 不要验证（留给 M2） |
|---|---|
| 呼吸包络能否被手指 / 掌心感知 | 整机结构、毛绒一体机芯装配 |
| 咕噜 25~50Hz 哪个频点最有「猫感」 | 摇尾机构最终结构 |
| 谷底断电能否消除嗡鸣 | 云功能、NFC、无线充电 |
| 目标毛绒厚度下的噪声实测值 | 电池续航（USB 供电即可） |
| 心情值参数（+2 / 100 / 70 / 90s）的手感校准 | 3C / GB 6675 认证（M0 / M5） |
| 触摸隔着绒层能否触发（只记录结论） | 触摸方案本身（独立课题） |

> **结论**：这次只验证**手感与声音**，不验证工程。**不要买贵的、不要做 PCB、不要开模。**

### 1.2 M0 必须并行启动，不要串行

| M0 事项 | 成本 | 周期 | 为什么现在启动 |
|---|---|---|---|
| 商标近似检索 | ¥300~1500 | 1~2 周 | 委托代理，自己查不准 |
| **摇尾机构 FTO 检索** | ¥2000~8000 | **2~4 周** | 正好在 M1 结束前出报告 |
| 认证路径咨询（先问报价，不急送检） | ¥0 | — | 3C + GB 6675 周期最长，是 M3 之后的主要不确定项 |

**这是本项目最不该省的钱。** 省下检索费的后果是产品做完发现侵权要下架，损失是 10 倍以上。FTO 检索要 2~4 周，你做 PoC 也要 4 周——**并行启动，别串行**。等 PoC 做完再想起检索，又要等一个月。

## 4. 体感线：逐日操作（8 个工作日）

### 4.0 Day 0：烧录前必做（**易被漏掉，漏了会浪费一整天**）

```bash
# ① 编译烧录（调试配置：CLI 可用，摇尾只算不输出）
#    Arduino IDE 选板：ESP32 Dev Module，波特率 115200
# ② 首次上电，NVS schema 与 PoC 不兼容，必须先重置
RESET ALL
SAVE

# ③ 确认固件与配置来源
info
status
```

| 现象 | 含义 |
|---|---|
| 旧固件的参数值「莫名其妙还在」 | NVS schema 不匹配被忽略是**正确行为**，但必须 `RESET ALL` + `SAVE` 才能写入新出厂值 |
| `SET` 被拒绝并回报规则号 | **设计意图，不是 bug**。v1.0 越界值**拒绝而非静默钳制**——静默钳制会让 `t gate 99` 看似成功实际夹到 60Hz，导致整份扫频记录不可信 |

### 4.2 Day 2：单马达裸测（**最有价值的一天**）

一次性回答两个关键问题：「谷底断电到底有没有用」「哪个区间最安静」。

```bash
# ① 让马达转起来，确认接线
t bare 100              # 满占空比
t barestop

# ② 找起转阈值：占空比从 0% 逐步升到 100%，记录「开始转」的临界值
t bare 5
t bare 10
t bare 15               # ...逐点试，直到稳定转动
t barestop

# ③ 扫低频噪声：在「刚能转」到「稳定转」之间取 5~8 个点，每点用声级计测
t bare 20
t bare 30
t bare 40
t barestop

# ④ ★ 波谷 A/B 对比（本日核心）
t trough 0              # A 组：谷底完全断电
t trough 20             # B 组：谷底保留 20%
```

| 记录项 | 说明 |
|---|---|
| 起转占空比 | 这个临界值就是「嗡鸣区」的上界，是 `P-41` 谷底取 0 的依据 |
| 各点噪声 | 找出噪声最小的工作点 |
| A/B 噪声差 | **判据：0% 比 20% 噪声低 ≥3dB** |

> **若 A/B 结论成立，`C-18` 校验规则即被实证。** 若差距 <3dB，说明低占空比区没有明显嗡鸣，可以复核 `C-18` 是否值得强制。
> `t trough 20` **故意绕过 `C-18`**，仅供实验；想真正改 `breath_trough_duty_pct` 会被规则拒绝——这也是设计意图，建议在 Day 7 顺手演示一次。

## 5. 摇尾线：逐日操作（14 天）

### 5.0 v1.0 在摇尾线能做什么、不能做什么（**能力边界，必须先读**）

**必须先明确一点**：摇尾是一个**机构（mechanism）问题，不是电机（motor）问题**。市面上不存在「摇尾专用电机」这个品类。

| v1.0 能提供 | v1.0 不提供 |
|---|---|
| 档位 → 频率 / 幅度的**计算逻辑**（W1~W4） | **执行器驱动信号**（默认 `ENABLE_TAIL_OUTPUT=0`） |
| ease-in-out 平滑过渡（`P-51` / `P-52`） | 舵机所需的脉宽调制 |
| ±`P-49` 频率抖动 | 机构结构与限位标定 |
| 无互动 `P-53` 自动停摆 | 堵转保护 |
| `t tail 1..4` 直接设档位观察计算值 | 过热保护（FR-05 快摆 30 秒） |
| 全部逻辑有测试覆盖 | — |

**关于执行器驱动，有一个精确的结论**：

`config.h` 中 `TAIL_PWM_FREQ = 50` —— **已经是舵机帧率**（50Hz / 20ms 周期）。但 `tail.cpp` 的占空比映射是：

```
duty = 50 + sin(phase) × ampNorm × 25      →  25% ~ 75% 占空比
```

在 50Hz 下即 **5ms ~ 15ms 脉宽**，这是**面向 H 桥（DRV8833）驱动直流电机的双向调速信号**（50% = 停转，<50% / >50% = 两个方向）。

**舵机要求的是 0.5ms ~ 2.5ms 脉宽（2.5% ~ 12.5% 占空比）**，因此：

| 走哪条路线 | 需要做什么 |
|---|---|
| **舵机方案（推荐）** | 改占空比映射：`duty = 7.5 + sin(phase) × ampNorm × 5`（中心 1.5ms）。**一个常量的事**，因为载波频率已经对了 |
| **N20 + H 桥方案** | 直接置 `ENABLE_TAIL_OUTPUT = 1`，接 DRV8833，**现有映射就是对的** |
| 仅做拆解与频率验证 | 不需要固件，用舵机测试仪 + 手机慢动作录像 |

> 本基线不包含舵机驱动实现，这是**刻意的边界**：机构选型属《M1-PoC执行清单-摇尾机构与选型》的范畴，v1.0 只负责「档位 → 频率/幅度 → 平滑过渡」的计算与状态输出，不越界接机构。

| 2.1 | 舵机测试仪测基本动作 | 手动调角度 | 响应是否顺滑 |
| 2.2 | 测最大摆动频率 | 写循环逐步加快 | 能达到的最大 Hz |
| 2.3 | **带负载测频率** | 尾端挂重物（模拟毛绒尾巴 20~50g） | 频率下降多少 |
| 2.4 | **四档频率可达性验证** | 分别试 W1(0.3) / W2(0.6) / W3(1.2) / W4(2.0) Hz | **哪一档达不到** |
| 2.5 | 测噪声 | 各档位噪声 | 数据 |
| 2.6 | 测堵转电流 | 手动阻止尾巴 | 评估电源需求 |

**2.4 是核心验证。** 若 SG90 带负载后达不到 2.0Hz，两个选择：① 降低 W4 要求；② 换 N20 减速电机（转速更高）。**这个结论直接决定选型。**

> 技巧：用手机 120fps 慢动作录像数摆动次数，不需要买转速表也能得到 ±5% 精度的数据。

**记录**：`field-forms.html` 表 11。

### 5.3 Day 5-7：N20 方案验证（路线 C）

| # | 任务 | 方法 | 记录项 |
|---|---|---|---|
| 3.1 | 三种减速比分别测空载转速 | 光电测速或慢动作录像 | rpm |
| 3.2 | 换算摆动频率 | 曲柄方案：摆动频率 = 转速 / 60 | Hz |
| 3.3 | 验证能否覆盖 W1~W4 全频段 | **0.3Hz 需要极低转速**，只有高减速比才能做到 | 覆盖结论 |
| 3.4 | 装配 AS5600 测角度闭环 | 验证能否精确控角 | 角度误差 |
| 3.5 | 测空载 / 堵转电流 | 万用表 | **堵转可达 500mA，电源建议额定 2A 以上** |
| 3.6 | **测回程间隙（backlash）** | 正反转，测空转量 | 间隙大小 |

**3.6 是个容易被忽略但很重要的点**：N20 减速电机的齿轮间隙会导致「尾巴在换向时有一小段空转」，表现为**动作不跟手**。舵机是闭环的，**没有这个问题**；N20 开环有，加编码器闭环能改善但成本上升。**这是选型的核心权衡点之一。**

**记录**：`field-forms.html` 表 11。

### 5.4 Day 8-10：寿命测试

**时间换算**：舵机以 0.6s/次计，1 万次 = 6000 秒 = **约 1.7 小时**连续运行。**一晚上就能跑完。** 跑 3 轮（约 5 小时）达 3 万次，超过门禁要求。

| # | 任务 | 方法 |
|---|---|---|
| 4.1 | 接上舵机/N20，写循环代码 | ESP32 让它不停摆 |
| 4.2 | 连续跑 1 万次 | 约 1.7 小时，睡一觉就跑完 |
| 4.3 | 中途记录 | **每 1 小时看一次**，记录异响 / 卡顿 / 发热 |
| 4.4 | **跑完拆解检查** | 齿轮磨损、轴套间隙 |
| 4.5 | 可选：加跑到 3 万次 | 验证裕度（M3 要求 10 万次，M1 先看趋势） |

**4.4 是关键**：跑完之后拆开看磨损位置。**磨损在哪，就是设计要加强的地方**——这是自研机构的直接输入。

> **注意 PRD v1.1 新增的耐久要求**：摇尾机构须支持 **W4 档（2.0Hz）连续运行 ≥30 分钟不失效**。建议在寿命测试中单独安排这一段，因为连续快摆的发热与磨损与间歇摆动不同。

**记录**：`field-forms.html` 表 13。

**决策树**：

```
摇尾 PoC 结束
  │
  ├─ 现成机芯有可用的 & 专利风险低？
  │    ├─ 是 → 评估「机芯贴牌」路线（省开发成本，但无差异化）
  │    └─ 否 → 继续
```

| 判据 | 后果 |
|---|---|

## 7. 风险与合规（不要跳过这一节）

### 7.1 本项目真实存在的约束

| 事项 | 现状 | 必须怎么做 |
|---|---|---|
| 摇尾传动专利密集 | RK-01 风险等级 20（高） | M0 完成 FTO 检索；**拆解观察不能替代代理机构报告** |
| 机构寿命 | RK-08 风险等级 9（中） | M1 做 1 万次验证，M3 前完成 10 万次 |
| 认证周期长 | 3C + GB 6675，M1 结束前须确认路径 | **M0 就开始问报价**，不要等产品做完 |
| 毛绒玩具标识 | 须标注产品名称、适用年龄、执行标准、厂名厂址、警示语、主要成分、维护保养说明 | 纳入 M4 说明书评审门禁 |

### 7.2 拆解与专利的边界（重要）

> 现成机芯的传动结构（普遍为「曲柄—连杆—摇杆」或「双减速箱 + 摇杆」）**可能落入他人在先专利范围**。供应商通常无法提供完整的专利授权链与 FTO 说明，**一旦侵权，责任由品牌方承担**。
>
> **本次拆解的目的是「获取规避设计的输入」，而不是「获得专利洁净性结论」。** 后者必须由具备资质的代理机构出具检索报告。

### 7.3 一条 OPC 的战略提醒

**参数化是护城河。** 一个人做硬件，不可能靠机构精度取胜。但 **75 项可调参数 + 状态机编排是纯软件资产**——改一行就换一种性格。这是 OPC 相对大厂唯一的结构性优势：**大厂改参数的流程成本比你高得多。**

## 8. 常见坑（含 v1.0 建设过程中踩到的）

| # | 坑 | 后果 | 规避 |
|---|---|---|---|
| 1 | 首次烧录没做 `RESET ALL` + `SAVE` | 旧 NVS blob 的残留值干扰调参记录 | Day 0 第一件事就是它（v1.0 schema=2，与 PoC 不兼容） |
| 2 | 以为 `SET` 被拒绝是 bug | 误判固件有问题，浪费排查时间 | v1.0 **拒绝而非静默钳制**是刻意设计。静默钳制会让记录不可信 |
| 3 | 在毛绒上直接做电容触摸 | 静电误触发 + 绒长导致灵敏度骤降 | **本次只记录结论，不解决**。TTP223 厂商指南明确「避免使用含金属颗粒或易带静电的材料（如某些毛毡）」——毛绒恰好两者都占 |
| 4 | 没先测环境本底噪声 | ≤45dB 的判据失去意义 | Day 1 先测，目标 ≤35dB |
| 5 | 用手机 App 测 30Hz 低频噪声 | 低频段误差大，拿不到可信数据 | **买 ¥80 声级计**（P14） |
| 6 | 自己人做盲测被试 | 数据无效 | 被试不能是参与调试的人 |
| 7 | 用了旧版 PoC 固件做 `t feed` | **状态机在喂入期间停摆**，「降落是否平滑」观察不到 | 用 v1.0；其 `t feed` / `t auto` 已改为非阻塞调度 |
| 8 | 扫频时听不出 6 个频点差异 | 扫频记录全部无效 | 用 v1.0；门控调制已补齐，频率**真正驱动输出** |
| 9 | 增删参数后没加 schema 版本 | 旧 blob 被按新布局误读 | 增删参数必须 `PARAMS_NVS_SCHEMA + 1`；**只改默认值不用加** |
| 10 | 拿拆解观察当 FTO 结论 | 法律风险 | 必须委托代理机构 |
| 11 | 毛绒买了含银离子抗菌面料 | 干扰电容触摸 | 下单前问清「不含金属纤维 / 不含银离子抗菌」 |
| 12 | 尾巴做太重，舵机摆不动 | 频率大幅下降 | **尾巴必须轻量化**（轻质骨架 + 短毛绒），这是舵机方案的硬约束 |
