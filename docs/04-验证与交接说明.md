8. 参数名查找 / 钳制 / 规则说明文案
9. NVS 持久化与 schema 版本守卫（含版本不匹配时忽略旧 blob）

**`test_mood`（16 段）**
1. 抚摸累积至触发咕噜
2. 咕噜期间：不叠加、档位锁 W4
3. 咕噜结束 → 平滑降落 → 冷却

6. 摇尾档位随心情值切换（含 `P-50` 迟滞防抖）
7. 咕噜时长映射：单调、无断崖、两端可分辨

9. 防抖：首次抚摸必响应，过快重复被过滤
10. 呼吸触发链路与 `P-43` 节流
11. 呼吸与咕噜互斥（咕噜优先）
12. 咕噜轮次间隔闸门（`P-30`）
13. 累计连续运行上限（`P-31`）
14. 降落曲线三选一（`P-16`）且 `P-17` 段数可区分
15. 系统态优先级（安全类 > 咕噜 > 呼吸 > 待机）
16. 心情值不做掉电持久化（FR-37d）

**`test_haptic`（7 段）**
1. 呼吸包络：谷底 0%、峰值达标、曲线平滑、周期在 3000~5000ms
2. **咕噜门控调制：`P-32` 确实落到输出**
3. 咕噜淡入/淡出（FR-36⑧：禁止骤起骤停）
4. 时长截断与保护（`P-29` / 下限）
5. 互斥与优先级（提示震可打断呼吸，不可打断咕噜）
6. 扫频推进与自动收尾
7. 裸测与占空比直写

**`test_cli`（8 段）**
1. 帮助与固件信息（含编译开关可核查）
2. 参数查询（按组 / 单个 / 未知参数提示）
3. 写入校验拦截（`C-02` / `C-16` / `C-18` / `X-01` 被报出，且参数实际未改动）
4. 枚举取值按名写入
5. `DUMP` 导出与 `PRESET` 切换
6. 体感测试命令（含 `t gate` / `t trough` / `t cycle`）
7. **非阻塞抚摸模拟**（馈入期间状态机仍能推进）
8. 状态快照与容错（空行不刷屏）

**`build_check`（3 段，两种编译配置各跑一遍）**
1. `setup()` 可完成初始化（含 NVS 与三层参数落地）
2. `loop()` 可长期推进且状态机可完整跑完一轮
3. 调试通道的编译期隔离

## 3. 本机测试的边界（必读）

### 3.1 它能证明什么

| 能证明 | 机制 |
|---|---|
| 逻辑自洽 | 264 条断言覆盖状态机时序、映射形状、闸门、链路 |
| 参数约束生效 | 21 条规则逐条断言，含拒绝后原值不变 |
| 波形数学正确 | 用假时钟步进采样 `ledcWrite` 记录，断言包络形状 |
| **驱动频率真的落到输出** | 断言输出只含 0/满量程，且 50Hz 切换次数 > 20Hz |
| 真实入口可用 | `build_check` 直接调 `setup()` / `loop()` |
| 量产配置可用 | `ENABLE_DEBUG_CHANNEL=0` 下编译、链接、运行 |

### 3.2 它**不能**证明什么

| 不能证明 | 为什么 | 谁来证明 |
|---|---|---|
| 呼吸有没有机械嗡鸣 | 桩不产生声音 | 人耳，烧录后 |
| 咕噜像不像猫 | 桩不模拟机构与声学 | 人耳，`t gate` 扫频 |
| 摇尾过渡是否自然 | 桩不模拟机构惯性 | 人手 + 眼 |
| 马达起转阈值 | 桩不模拟负载 | `t bare` 实测 |
| 结构噪声、共振点 | 桩不模拟装配 | 实测 |
| 功耗与发热 | 桩不模拟电流 | 实测 |

> **一句话**：`run_tests.sh` 全绿意味着「可以进入烧录阶段」，不意味着「手感达标」。

### 3.3 假时钟是如何工作的

`test/arduino_stub.cpp` 提供 `g_fake_ms` / `g_fake_micros`，`millis()` 返回假时钟，
`delay(ms)` 也推进假时钟。测试用 `runFor(ms, stepMs, fn)` 模拟真实 loop 频率：

```cpp
runFor(20000, 5, [&]() { h.tick(); });   // 以 5ms 步进推进 20s
```

因此固件里**禁止 `delay()` 阻塞**这条约定，不只是代码规范——它直接决定了
状态机在测试中能否被推进。原 PoC 的 `t feed` 用 `delay(1200)` 阻塞，
结果「喂入期间观察降落是否平滑」这件事根本观察不到；v1.0 改为基于 `millis()` 的
调度，并用「馈入期间状态机仍能推进」断言守住。

## 4. 与 M1 执行清单的对应关系

| M1 事项 | 本基线提供的支撑 | 仍需人工完成 |
|---|---|---|
| Day2 波谷 A/B 对比（呼吸嗡鸣） | `t trough 0` / `t trough 20`，`C-18` 锁定默认值 | 贴耳试听并记录 |
| Day2 裸马达起转阈值 | `t bare <duty>` | 实测起转点与噪声 |
| Day4 呼吸包络手感 | `t breath 1\|2\|3` 三档 + 包络数学已有断言 | 手感评分 |
| Day5 扫频找猫感区间 | `t sweep`（25→50Hz，每频点 10s）、`t gate <f>`（单频点微调） | **听感判定，本机无法替代** |
| Day5 咕噜时长映射 | `t feed` 走完整状态机；映射单调无断崖已有断言 | 主观时长偏好 |
| Day7 长时间稳定性 | `t auto`（无限循环，非阻塞） | 挂机观察 |
| 波谷/嗡鸣、咕噜像不像猫、过渡是否自然 | — | **M1 门禁证据的唯一来源** |

> **交接提醒**：M1 门禁证据的形式是**主观评分记录 + 参数定稿值**，而不是测试输出。
> 本基线把「改参数 → 立即试听」的往返成本从「分钟级（重烧）」降到「秒级（串口）」，
> 这正是 M1 能在 8 个工作日内完成调参的前提。

## 5. M1 门禁前的必做动作

```text
① 烧录调试配置
   -DENABLE_DEBUG_CHANNEL=1 -DENABLE_TAIL_OUTPUT=0

② 首次上电先清空 NVS（schema 与 PoC 不兼容）
   RESET ALL
   SAVE

③ 确认波谷必须是 0
   GET breath_trough_duty_pct          → 期望 0
   t trough 0 / t trough 20            → 对比试听，记录是否有嗡鸣差异

④ 扫频找猫感区间
   t sweep                             → 25/30/35/40/45/50Hz，每档 10s
   记录每档评分；再用 t gate <f> 在最优档附近细调

⑤ 确认咕噜手感与时长映射
   t purr 20                           → 纯体感（不走状态机）
   t feed 40                           → 走完整状态机，观察触发/降落/冷却
   t cycle                             → 从当前心情值跑一次完整生命周期

⑥ 确认摇尾逻辑（无机构时）
   t tail 1 / t tail 4                 → 观察过渡是否平滑、是否锁 W4

⑦ 定稿并落盘
   SET purr_drive_freq_hz <找到的值>
   SAVE

⑧ 交付量产配置
   -DENABLE_DEBUG_CHANNEL=0 -DENABLE_TAIL_OUTPUT=<接机构后为 1>
```

## 6. 已知限制

| # | 限制 | 影响 | 规避 / 后续 |
|---|---|---|---|
| 1 | **触摸判定未接入** | 无法真实触摸唤醒 | `config.h` 已定义 `TOUCH_PIN_*` 与 `TOUCH_THRESHOLD`；M1 用 `t feed` 从串口注入抚摸事件。接入真实触摸后，`P-05 pet_valid_min_ms` 应改由触摸驱动的「按下持续时长」判定（当前实现取 `max(P-06, P-05)` 作为事件间隔） |
| 2 | `LOWPOWER` / `UPGRADING` 是占位态 | 无低电保护、无 OTA | 状态、优先级、`purrGateState() == PG_SYSTEM` 均已实现且可经 `t state` 验证；只需接入电池 ADC / OTA 触发源 |
| 3 | 云端参数层未启用 | 无法远程改参 | 接口已留，`config_cloud_enabled` 默认 0。**关键约束已落实**：拉取失败必须保持本地值，禁止回落硬编码 |
| 4 | 摇尾只有逻辑层 | 无物理动作 | `ENABLE_TAIL_OUTPUT=0`；输出通路已在 `tail.cpp` 实现并被测试覆盖，接机构即可用。机构选型属另一份执行清单 |
| 5 | NVS schema `2` 与 PoC 不兼容 | 从 PoC 升级会忽略旧配置 | 首次烧录执行 `RESET ALL` + `SAVE`；未来参数增删必须 `PARAMS_NVS_SCHEMA + 1` |
| 6 | 无真实触摸/机构/声学的仿真 | 手感无法本机验证 | 见 §3.2，必须烧录后人工判定 |
| 7 | 参数一致性靠规则而非自动同步 | 改阈值需手动同步 `purr_tier_b0` 等 | 由 `X-01` / `C-05` / `C-11` 强制拦截并提示，不会静默出错；`PRESET` 命令已自动处理 |

## 7. 维护须知

### 7.1 修改参数表时的检查清单

1. 改 `params.h` 的 `enum ParamId` → 同步改 `params.cpp` 的 `META` 表（**顺序必须严格一致**，
   `test_main` 的「枚举/META 顺序一致」段落会拦截错位）。
2. 数值变更 → 检查是否触发其他规则（如改 `purr_trigger_threshold` 需同步 `purr_tier_b0`）。
3. 增删参数 → `config.h` 的 `PARAMS_NVS_SCHEMA **+1**`。
4. 跑 `bash test/run_tests.sh`，必须 264/264 全绿。

### 7.2 新增校验规则时的检查清单

1. 在 `Params::validate()` 中加判定，返回规则号（如 `"C-19"`）。
2. 在 `Params::ruleText()` 中加人类可读说明——**CLI 与文档都引用它，不要另写一套文案**。
3. 在 `test_main.cpp` 补正反两个断言（违反被拒 + 边界通过）。
4. 在本文档 §8 全表补一行。

### 7.3 不允许的写法

| 禁止 | 原因 |
|---|---|
| 在 `.cpp` 里写体感数值字面量 | 违反 FR-38；应加入 `META` 表 |
| 在 `tick()` / `poll()` 路径中 `delay()` | 阻塞状态机；见 §3.3 |
| 绕过 `enterState()` 直接改 `m_state` | `m_stateStart` 与副作用会失同步 |
| 让 `haptic.*` 感知「心情值」语义 | 破坏可测性（应传档位/时长，不传心情值） |
| 让 `tail.*` 做机构选型判定 | 越界，属另一份执行清单 |
| 用 `params.cpp` 执行动作（发 PWM / 改状态） | 破坏「参数只描述配置」的边界 |
