# 01 · 设计意图与核心目标

> 本文回答三个问题：**为什么要做这套固件、它要达成什么、它的边界在哪里。**
> 阅读顺序建议：本文 → `02-关键结构与模块边界.md` → `03-参数体系与校验规则.md`。

## 1. 设计意图

### 1.1 一句话

毛绒电子宠物要让人觉得「活着」，靠的不是硬件堆料，而是**震动在时间轴上的变化方式**。

### 1.2 核心判断

一只毛绒玩具是否有生命感，取决于它在**没有明显动作**的时候是否仍在「呼吸」。因此本项目
把「生命感」拆解为两个可独立验证的物理通道：

| 通道 | 承担的生命感 | 对应需求 |
|---|---|---|
| 振动马达 | 呼吸（静息状态的存在感）、咕噜（被抚摸后的满足感） | FR-35 / FR-36 |
| 摇尾机构 | 情绪等级的外显（兴奋度分级、情绪过渡） | FR-39 / FR-39a |

两个通道由**同一个心情值**驱动，并由 **FR-40 / FR-40a 的平滑过渡**约束其切换方式——
这是「像活物」与「像电机」的分界线。电机是阶跃的，活物是渐变的。

### 1.3 三条设计原则

这三条原则贯穿全部代码，也是理解参数表为何如此设计的钥匙：

**原则一：行为参数全部外置，代码里不出现行为常量（FR-38）。**

固件源码中不存在 `0.65f`、`20000` 这类体感数值，所有行为数值集中在 `params.cpp` 的 META 表
（75 项）。理由是 M1 阶段的本质工作是**调参**而非写代码：如果「咕噜多久」「呼吸多深」写死在
`.cpp` 里，每试一个值就要重编译烧录一次，一轮数分钟，M1 的 8 个工作日根本不够用。
把参数外置后，`SET purr_duty_base_pct 70` 立即生效，配合 `SAVE` 再落盘。

**原则二：非法配置必须在写入前被拒绝，而不是在运行时表现为怪现象（FR-38b）。**

参数之间存在真实耦合。例如「降落终点值 ≥ 触发阈值」会导致咕噜结束后瞬间重新触发，
形成无限咕噜死循环；「波谷占空比 > 0」会在低占空比区产生机械嗡鸣。
这类问题在运行时的表现是「玩具抽风」，但在参数层面只是一个数值越界。
固件把 21 条耦合约束编码为校验规则（`C-01`~`C-18` + `X-01`~`X-03`），
任何写入先试算、违反则拒绝并回报规则号与人类可读说明。

**原则三：量产不留运行期后门（FR-38c / RK-23）。**

调参入口（CLI）经编译期开关整体移除，而不是运行时隐藏。量产配置下约 570 行命令实现
完全不进二进制，且启动时明确打印「调试通道已编译移除」——避免出现「以为关了其实没关」
或「以为开了其实已移除」的双向误解。

## 2. 核心目标

### 2.1 v1.0 要达成的目标

| # | 目标 | 可验证的完成标志 |
|---|---|---|
| G1 | 五项体感机制全部有可运行实现 | FR-35 / FR-36 / FR-37 / FR-39 / FR-40 在代码中均有对应模块与测试 |
| G2 | 参数可在不重烧固件的前提下调整 | `SET` 立即生效；`DUMP` 导出 75 项；`SAVE` 断电保持 |
| G3 | 非法参数组合无法写入 | 21 条校验规则全部有断言覆盖，且拒绝后原值不变 |
| G4 | 逻辑正确性可在无硬件条件下验证 | `bash test/run_tests.sh` 一行跑完，6 套件 264 断言全绿 |
| G5 | 调试配置与量产配置都能编译运行 | `build_debug` / `build_release` 两个套件各 16 条断言 |
| G6 | M1 现场有明确的调参路径 | `t gate` 找猫感区间、`t trough` 做波谷 A/B、`t feed` 跑完整生命周期 |

### 2.2 明确的非目标（v1.0 不做）

划清边界比堆功能更重要，以下事项 **v1.0 刻意不做**，理由是它们属于其他执行清单或后续版本：

| 非目标 | 归属 |
|---|---|
| 摇尾机构选型、连杆设计、限位标定 | 《M1-PoC执行清单-摇尾机构与选型》 |
| NFC 周边联动的读卡与配对逻辑 | 后续版本（体感子系统先行） |
| 云端参数下发通道的实际启用 | 仅留接口，`config_cloud_enabled` 默认 0 |
| 电池 ADC 低电检测、OTA 升级实现 | 状态与优先级已实现，触发源待接 |
| 触摸电极的采样与校准 | v1.0 用串口注入抚摸事件替代（见 `04` 已知限制 1） |

> 取舍说明：v1.0 选择「把一个子系统做完整」而不是「把整机做半个」。
> 摇尾的**逻辑层**（档位 → 频率/幅度 → 平滑过渡）在本版中完整实现并测试，
> 只把**机构层**留给选型清单——接口已就位（`ENABLE_TAIL_OUTPUT`），接上机构即可用。

## 3. 「像活物」在代码中的五处落点

设计意图必须落到可检查的代码结构上，否则只是一句口号。以下五处是「生命感」的具体载体：

### 3.1 呼吸的谷底必须是 0%，而不是「很小」

`P-41 breath_trough_duty_pct` 默认 `0`，且被校验规则 `C-18` 强制锁定为 0。

**原因**：马达在低占空比（约 3%~15%）区间会产生明显的机械嗡鸣，听感是「电流声」而非
「呼吸」。只有完全断电（占空比 0）才能让一个呼吸周期的收尾真正安静下来。
这不是美学偏好，而是「有嗡鸣就不像活物」的硬性判断。

### 3.2 咕噜必须有驱动频率，且频率必须真的落到输出

`P-32 purr_drive_freq_hz`（默认 30Hz）通过**门控调制**实现：在每个 `1/f` 周期内，
按目标平均占空比导通一段、断开一段。平均功率与占空比一致，同时在 `f` 上产生震颤感。

**为什么这是关键**：如果驱动频率只被读进一个变量、从未影响输出，那么
「扫频 25→50Hz 找猫感区间」这项 M1 核心实验在物理上**不产生任何差异**——
操作者会听到 6 个一模一样的频点，然后得出「频率不影响手感」的错误结论。
v1.0 把门控调制作为一等实现，并用「输出只含 0 与满量程两种状态」「50Hz 的通断次数
显著多于 20Hz」两条断言把它钉死。

### 3.3 时长映射不能有断崖

心情值 104 → 105 时咕噜时长不应跳变 10 秒。PRD 附录 C 的 `P-25`~`P-26` 用
**4 段 5 锚点分段线性**描述映射曲线，v1.0 在此基础上同时支持
`P-24` 的线性模式，并用「单调 + 无断崖」断言约束两者。

**断崖为什么致命**：用户感受到的不是「时长变长」，而是「玩具突然疯了」。

### 3.4 降落、冷却期的抚摸必须给反馈

`FR-37c` / `FR-40④` 要求：降落期与冷却期的抚摸**一律不计分，但必须给可感知反馈**。

**原因**：不给反馈会被判定为「玩具失灵」。用户不会推理「哦现在是冷却期」，
只会认为「它不理我了」。因此实现上，降落期给一次柔震（`P-18`），
冷却期给一次更重的拒绝震（`P-21`）——「感受得到，但不给奖励」。

### 3.5 咕噜期间摇尾锁 W4

`FR-39` 的验收条件是：咕噜进行中摇尾必须是 W4（最高档）。v1.0 在 PURR 状态进入时
直接锁定档位，而不依赖迟滞判定——避免「心情值刚回落导致咕噜期间摇尾降档」的观感错误。

## 4. 交付边界与验证分层

本基线固件的验证分三层，越往下越贵、越晚做：

| 层级 | 手段 | 本轮状态 |
|---|---|---|
| L1 逻辑正确性 | `bash test/run_tests.sh`，假时钟 + Arduino 桩 | ✅ 6 套件 264 断言全绿 |
| L2 编译形态 | 调试 / 量产两种配置的编译与启动 | ✅ `build_debug` / `build_release` |
| L3 真实体感 | 烧录后上手听、贴耳听、摸 | ⬜ **必须在硬件上做**，本机测试无法替代 |

> **交接提醒**：L1/L2 全绿只说明「逻辑自洽、能跑起来」，不代表手感达标。
> 呼吸是否有嗡鸣、咕噜像不像猫、摇尾过渡是否自然，这三件事只能由人耳和手来判定，
> 且必须在 M1 门禁前完成。详见 `04-验证与交接说明.md`。
